One shared Twilio/Africa's Talking/Hubtel account HNN can activate for a live test and deactivate again when done — used by any client below that hasn't set up its own. Whether this actually sends for real is controlled by the Messaging rail under Operating mode, not by anything on this card.

Patient verification by SMS/WhatsApp

When a channel is on, the patient verification link sent at billing time (and on resend) also goes out by SMS and/or WhatsApp, with a short code the patient can text back instead of opening the link. Off by default for every client; unrelated to the payer-side verification gate under Payers.

Operating mode

Settlement and Messaging switch independently — e.g. Messaging can go live while Settlement stays sandboxed, or vice versa. Once anything here is saved, it governs at runtime (no redeploy); the server's env vars only seed the very first default, before Master Control has ever saved anything.

Settlement — Stanbic / SBG disbursements

Real bank transfers once live. Going live moves real money, so it requires typing LIVE to confirm; going back to sandbox never does.

Settlement credentials — Stanbic / SBG

This payer's own Stanbic marketplace username/password, used to authorise the A2A transfer to a provider. Stored encrypted; falls back to a legacy plaintext credential already on the payer record if nothing's saved here.

Processing target

Set a volume an insurer/employer aims to process through HNN, and track settled value against it.

Patient verification gate

When on, this payer's claims can't be authorised until the patient has verified the bill via the link sent automatically at billing time.

Pre-approved price list

Upload an insurer's approved prices (CSV or Excel-exported CSV). Columns: code, name, price and optionally unit, provider, category. A provider (tenant id or facility name) gives that facility its own price; blank = the payer's default.

When on, claims routed to this payer are repriced to its approved prices (facility-specific first, then default, else the billed price). The patient absorbs any gap between billed and approved.

A payer's product team builds Value-Based-Care programs, promotional campaigns, and loyalty/discount programs here — no coding required. Every product starts as a draft, moves to sandbox to test against real observation data risk-free, then live once it's reviewed. Incentives, penalties and cashback only ever accrue as figures to review here — nothing disburses automatically yet. Clinical indicators (blood pressure, HbA1c, LDL, complications, follow-ups) come from an EMR/EHR partner's own feed — see the EMR/EHR partners tab for the API key a partner pushes them with.

Preview & accrue

Preview runs the scoring/reward engine and shows what it would pay out for a period — nothing is saved. Accrue runs the same engine and writes those figures to the ledger below it. Run each period once; accrual history shows what's already been recorded.
